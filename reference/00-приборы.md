# Этап 0. Приборы

Дашборд поднимается **первым**, до любого разбора: он и есть то, что владелец
открывает, пока автопилот работает. Без него прогон виден только в чате, а
чат сжимается.

## Сначала — не начался ли прогон раньше

`.designpilot/state.js` переживает сессию, а контекст — нет. Поэтому первым
делом:

```bash
ls .designpilot/state.js 2>/dev/null && cat .designpilot/state.js
```

| Что нашлось | Что делать |
|---|---|
| файла нет | новый прогон, дальше по этому файлу |
| есть, `finishedAt` пустой | **продолжение**: прочитать состояние, взять первую стадию не `done` и первый экран не `done`, сказать владельцу одной строкой, с чего продолжаем, и идти туда |
| есть, `finishedAt` заполнен | прошлый прогон сдан. Новая работа — новый `run`: переименовать старый файл в `state-<дата>.js` и завести свежий |

Начать заново поверх незакрытого прогона — потерять его находки и вопросы.

## Что поднять

```bash
A=$(git rev-parse --show-toplevel 2>/dev/null || pwd -P)/.designpilot
S=$(find -L ~/.claude/skills ~/.agents/skills .claude/skills .agents/skills \
      -maxdepth 6 -name dashboard-template.html -path '*designpilot*' 2>/dev/null | head -1)
[ -z "$S" ] && { echo "навык не найден по стандартным путям"; exit 1; }
S=$(cd "$(dirname "$S")" && pwd -P)
mkdir -p "$A"
cp "$S/dashboard-template.html" "$A/dashboard.html"
cp "$S/sync.py" "$A/sync.py"
ln -sfn dashboard.html "$A/index.html"
echo "skillDir = ${S%/scripts}"
```

Каталог **`.designpilot/`**, а не `.autopilot/`: в репозитории может идти
прогон скилла `autopilot`, и два инструмента, пишущие в один `state.js`,
затирают друг друга.

Пять корней, и `.agents/skills` среди них не случайно: установщик `npx skills`
кладёт навык именно туда, а в `.claude/skills` ставит симлинк. Отсюда же
`find -L` — без него симлинк не разворачивается, и файл «не находится», лёжа
на месте.

**Пустой результат `find` — это остановка, а не мелочь.** Без проверки
`dirname ""` даёт `.`, и копирование идёт из корня репозитория: команда
падает на первом же обязательном шаге прогона. Не нашлось — сказать владельцу
и попросить путь к навыку, а не искать обходной путь.

`index.html` — симлинк, а не копия: без него статический сервер отдаёт на `/`
листинг каталога, и владелец читает имена файлов вместо дашборда. Копия — это
второй дашборд, который стареет.

Путь к навыку записать в `state.js` как `skillDir`: из него берутся пресеты и
`audit.mjs`, а после сжатия контекста вывести его будет неоткуда.

## `state.js`

JSON в обёртке `window.STATE = {…}`. **Никаких выражений внутри** — `new Date()`
в файле означает, что дашборд не обновится.

```js
window.STATE = {
  "run": "Кабинет shainote",
  "mode": "ручной",
  "source": "Figma + живой сайт",
  "system": "core-vue",
  "skillDir": "/Users/…/.claude/skills/designpilot",
  "startedAt": "2026-08-24T20:00:00Z",
  "updatedAt": "2026-08-24T20:41:00Z",
  "finishedAt": null,
  "stages": { "intake": { "state": "done", "note": "что здесь произошло — одной строкой" },
              "discovery": { "state": "active", "note": "" }, "system": { "state": "pending", "note": "" },
              "plan": { "state": "pending", "note": "" }, "work": { "state": "pending", "note": "" },
              "verify": { "state": "pending", "note": "" }, "ship": { "state": "pending", "note": "" } },
  "crew": [{ "role": "QA-инженер", "model": "sonnet",
             "state": "working",          // working | done | idle
             "stage": "verify",           // на каком этапе вступила
             "runs": 1,
             "does": "нажимает каждый контрол и сверяет надписи",
             "now": "Обходит десять экранов и нажимает всё подряд" }],
  "crewNote": "если роли не запускались — сказать это и назвать причину",
  "log": [{ "stage": "verify", "role": "QA-инженер",
            "text": "вступил в работу: обход десяти экранов руками" }],
  "discovery": { "note": "", "blocks": [{ "name": "Шапка", "items": ["чип", "заголовок", "три показателя с иконками"] }] },
  "screens": [{ "name": "Сегодня", "state": "todo", "checked": "—", "note": "",
                "url": "http://localhost:5173/today", "sourceUrl": "https://…/dashboard",
                "tasks": [{ "text": "Снять инвентарь боевой страницы", "by": "haiku", "state": "done" }],
                "parity": { "kept": 6, "keptNote": "шесть блоков в том же порядке",
                            "changed": [{ "what": "лид сокращён", "why": "шаг за рамку — назван, не скрыт" }],
                            "lost": [] },
                "review": { "by": "sonnet", "verdict": "ok", "text": "" } }],
  "defects": [{ "text": "Кнопка входа: белый на #a9d3c8 = 1.7:1 при норме 4.5", "fixed": false }],
  "questions": [{ "text": "Что происходит после кнопки «Создать аккаунт»?",
                  "where": "Регистрация", "assumed": "место помечено как незаполненное", "answered": false }],
  "recommendations": [{ "text": "Поиск ищет только по папкам, встреч 113",
                        "cost": "листает 113 строк или записывает заново",
                        "proposal": "поиск по названию и содержанию, ~день",
                        "status": "open" }],
  "links": { "prototype": "", "system": "", "artifact": "", "source": "" }
}
```

`state` экрана: `todo` · `wip` · `done`. Стадия: `pending` · `active` · `done`.
`state` задачи: `todo` · `done` · `skip`. `verdict` ревью: `ok` · `issues`.

Стадия принимается и голой строкой (`"intake": "done"`) — прогоны, начатые
старой версией, страницу не ломают. Но без `note` этап на дашборде молчит, а
владельцу нужно именно оно: не «этап пройден», а что там произошло.

**`links.system` — не украшение.** Дизайн-система, которую нельзя открыть и
посмотреть, для владельца не существует: он видит только слово «система» в
шапке. Ссылка на живую галерею отдаётся вместе со ссылкой на прототип.

## Что дашборд показывает и чего не показывает

Страница отвечает на пять вопросов, в этом порядке, и каждый её блок обязан
принадлежать одному из них:

| Блок | Вопрос |
|---|---|
| **Сводка** — четыре числа | где мы и что горит |
| **Конвейер** — восемь этапов | сколько пройдено |
| **Бригада** — карточки ролей | кто работает прямо сейчас и над чем |
| **Хроника** — лента событий | кто вступил, на каком этапе, с чем вернулся |
| **Этапы** — свёрнутые подробности | всё остальное, внутри своего этапа |

**Число, на которое нельзя ответить действием, сюда не попадает.** Прошлая
версия показывала «10 / 10 задач сделано», где задачи были заведены только у
одного экрана из одиннадцати: цифра выглядела достижением и означала пустоту.
Хорошее число: «0 дефектов открыто · найдено 42», «9 ждут вашего решения».

**Бригада — не украшение.** Владелец, глядя на результат, не может отличить
работу от везения. Строка «QA-инженер · работает · вошла на этапе „Проверка“»
показывает, что приёмка идёт; «ещё не вступала» — что её не было. Работающие
роли на странице шевелятся: покой и работа обязаны различаться без чтения.

**Хроника пишется по факту, а не задним числом.** Роль вступила — строка в
`log` и `crew[].state: "working"` сразу, до того как она вернётся с
результатом. Иначе дашборд показывает прошлое и бесполезен как дашборд.

## Ритуал обновления

После **каждой** правки `state.js` — одна строка:

```bash
python3 .designpilot/sync.py
```

Она проверяет разбор, вписывает снимок в страницу и поднимает сервер, если
тот умер. Забытый вызов стоит устаревшего снимка, но никогда — пустой
страницы.

**Ссылку отдать владельцу сразу**, одной строкой, и больше к этому не
возвращаться: дальше он смотрит сам.

## Что обновлять по ходу

| Когда | Что меняется |
|---|---|
| закрыт этап | `stages`, `updatedAt` |
| найден дефект | `defects` + строка с числом |
| дефект починен | `fixed: true` |
| задан вопрос | `questions` |
| найдено вне объёма | `recommendations`, статус `open` |
| владелец ответил на находку | `accepted` или `declined` — **не удалять** |
| получен ответ | `answered: true` |
| экран взят / сдан | `screens[].state`, `checked` |
| поставлены задачи экрана | `screens[].tasks` |
| экран сверен с исходником | `screens[].parity`, `screens[].review` |
| снят инвентарь исходника | `discovery.blocks` |
| запущено (или не запущено) задание субагенту | `crew[].runs` |
| роль вступила или закончила | `crew[].state`, `crew[].stage`, `crew[].now` + строка в `log` |
| поднят прототип | `links.prototype`, `links.system` |
| опубликован показ | `links.artifact` |
| прогон сдан | `finishedAt` |

Экран помечается `done` **только** после всех трёх проверок — линтера,
браузера и сверки с исходником — и при пустом `lost`.
