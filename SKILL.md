# Автопилот дизайна

Ведёт интерфейс от входа — макета, ссылки или папки с файлами — до работающего
прототипа, согласуя решения **до** работы, а не после.

> Не путать со скиллом `autopilot`: тот строит проект от брифа до кода —
> «собери мне сервис». Этот занимается **интерфейсом**: разобрать вход,
> поставить дизайн-систему, собрать экраны, проверить. Если продукта ещё нет
> вовсе — сначала `autopilot`.

## Два режима

Слово после вызова. Если не сказано — **ручной**: молчание не согласие.

| | Автопилот | Ручной |
|---|---|---|
| После согласования плана | делает все экраны подряд | показывает каждый экран и ждёт «ок» |
| Останавливается | только на развилке, которой не было в плане | на каждом экране |
| Когда брать | экранов много, макет подробный, время дороже точности | важен каждый экран, макет неполный, продукт живой |

**Гейт есть в обоих режимах** и снять его нельзя: разбор, дизайн-система и
план согласуются всегда. Автопилот покупает тишину **после** плана, а не
вместо него.

Необратимое — деплой, публикация, удаление, письма — гейт в любом режиме.

## Железные правила

Важнее любого этапа. Нарушение — брак, даже если результат красивый.

1. **Факт, а не впечатление.** «Кнопка бледная» — не находка. «Белый текст на
   `#a9d3c8` даёт 1.7:1 при норме 4.5» — находка.
2. **Ничего не выдумывать.** Нет данных — метка непроверенного, а не
   правдоподобная фраза. Имена, числа, тарифы, сроки — только от владельца.
3. **Проверять двумя слоями.** Линтер проверяет словарь, браузер — поведение.
   Полоска вкладок без панелей проходит любой линтер и остаётся ложью.
4. **Спрашивать только то, что меняет работу.** Остальное решать и называть.
5. **Не трогать вне объёма — но и не молчать о найденном.** Рамка «только
   стили» не отменяет экспертизы: то, что стилями не чинится, оформляется
   находкой с фактом, ценой и предложением, и решает владелец
   ([reference/находки.md](reference/находки.md)). Молча чинятся только явные
   поломки: отказ доступности с числом, обещание без функции, опечатка.
6. **Смотреть глазами.** «Собралось» — не «работает».

Файл этапа загружать **перед** началом этапа, а не все сразу.

**Механическую работу отдавать дешёвой модели** — правила и шаблоны заданий в
[reference/модели.md](reference/модели.md). Дело не только в цене: у субагента
свой контекст, и дамп по двадцати экранам не оседает в главном, который
тратится один раз и не возвращается.

## Входы

Один или несколько сразу; разбор каждого — в [02-разбор.md](reference/02-разбор.md).

- **Figma** — из голой ссылки на файл достаётся список страниц, дальше вглубь;
  переменные макета читаются как готовые токены, библиотеки — как чужая
  система, Code Connect — как карта «фрейм → компонент кода».
- **Живой продукт** — обход браузером, замеры, поиск дефектов поведения.
- **Файлы** — скриншоты, PDF, ТЗ: из них берутся структура и требования, но
  **не** поведение: его в картинке нет и придумывать его нельзя.

## Результат

Отдельный прототип рядом с продуктом (`prototype/` или `<имя>-prototype/`),
на наборе из `presets/`. Продукт не трогается, пока владелец не скажет.
Показ — артефактом по одной ссылке, которая обновляется между заходами.

## Дашборд

Поднимается на этапе 0 и живёт весь прогон: `.designpilot/dashboard.html`
плюс `state.js` рядом. Владелец открывает ссылку и видит этапы, экраны,
найденные дефекты и вопросы, которые ждут ответа, — не читая чат.

Страница копируется из навыка один раз и **не правится**: состояние приходит
из `state.js`, снимок внутрь страницы вписывает `python3 .designpilot/sync.py`.
Поэтому дашборд показывает данные и открытый файлом, и с мёртвым сервером, и
через месяц после прогона.

Каталог `.designpilot/`, а не `.autopilot/`: в репозитории может идти прогон
скилла `autopilot`, и два инструмента, пишущие в один `state.js`, затирают
друг друга.

## Дизайн-система

Не спрашивается первым делом, а **ищется** — порядок в
[03-система.md](reference/03-система.md): код проекта → переменные Figma →
подключённые библиотеки → набор `presets/core-vue` → сборка из образцов,
которые покажет владелец. Спрашивается только выбор между найденным.
